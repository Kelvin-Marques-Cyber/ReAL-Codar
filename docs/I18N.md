# Idiomas humanos e linguagens de programação

`--lang` seleciona a linguagem do código. `--locale` escolhe o idioma humano do pedido; não traduz nomes de variáveis, caminhos nem strings do programa.

```sh
codar run 'x es igual a 10' --locale es --lang javascript --local --stages 0
codar config set ui.locale en
codar studio .
```

A paleta oferece **Idioma da interface**. A preferência é persistida; reabra o Studio para aplicar a todos os controles. `CODAR_LOCALE` também pode definir o idioma. Os recursos ficam em `src/codar/i18n/{pt-BR,en,es,pt-PT}.json`, com fallback para o texto original. Rótulos principais, navegação, controles de bibliotecas e trilhas usam esses recursos. Mensagens legadas e conteúdo didático não traduzido continuam em português; documentação e assinaturas de terceiros conservam o texto da fonte.

Português e inglês usam o front-end existente. Espanhol acrescenta um front-end conservador para atribuição, impressão, soma/média/produto/diferença, comparações, retorno, imports simples, condições e laços. Ele encaminha a construção para a mesma representação intermediária e emissores. Mantém indentação, identificadores e literais; construções não reconhecidas continuam no roteamento normal, sem alegação de cobertura universal. pt-PT compartilha a gramática portuguesa com recursos de interface próprios.

Os testes comparam resultados de intenções equivalentes nos quatro locales em Python, JavaScript, TypeScript, Go, Rust, Dart e PowerShell; também verificam blocos, strings, CLI e interface. Novos idiomas devem acrescentar recursos, um front-end quando necessário e testes de equivalência. Não se deve traduzir código pronto para implementar um idioma humano.
